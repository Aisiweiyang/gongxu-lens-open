# 供需透镜 · 商用试点手册（pilot-app v10）

## 1. 适用范围

单组织独立部署的再生材料替代决策工作台。首个场景：再生 PP 在非食品接触工业周转制品中
替代原生 PP。目标付费客户假设：园区运营方或循环化改造服务商（预算归属与付费意愿
待访谈验证，本手册不含任何付费承诺）。**不是**多租户 SaaS，不用于公网开放注册。

## 2. 角色

| 角色 | 权限 |
|---|---|
| 管理员 admin | 全部业务 + 用户管理、备份/恢复、审计查看 |
| 编辑 editor | 任务/供给/计算/选定/证据任务/反馈/预留 |
| 只读 viewer | 仅查看（服务端拦截所有写接口，不只隐藏按钮） |

## 3. 部署（干净环境）

```bat
:: 1. 创建独立虚拟环境（不修改任何其他项目的环境）
py -3.12 -m venv .venv
.venv\Scripts\pip install -r requirements.txt

:: 2. 初始化管理员（仅无任何账号时可执行；无硬编码默认密码）
.venv\Scripts\python pilot\init_admin.py --username admin --password <8位以上>

:: 3. 启动（默认 http://127.0.0.1:8765/）
.venv\Scripts\python pilot\start_pilot.py --host 127.0.0.1 --port 8765

:: 4.（可选）导入演示示例任务
.venv\Scripts\python pilot\import_sample.py --task demo01
```

安装后可离线运行（首次安装联网获取依赖；运行不依赖外网/CDN）。

## 4. 配置

- 因子表/核算约定/成本假设：`config/material_emission_factors.yaml`（演示假设因子
  须替换为真实因子库；核算约定不满足时引擎会阻断并输出具体字段）。
- 证据动作：`config/evidence_actions.yaml`。
- 数据库：默认 `pilot/data/pilot.sqlite3`（SQLite，WAL 模式）。

## 5. 备份与恢复

```bat
.venv\Scripts\python pilot\backup_restore.py backup                    :: 生成 pilot/backups/pilot-backup-*.sqlite3
.venv\Scripts\python pilot\backup_restore.py restore --source <备份文件>
```

恢复前自动校验备份文件合法性并做 WAL checkpoint（防旧日志重放毒化恢复数据）；
恢复为管理操作（仅 admin），每请求独立连接模型下恢复只影响当前请求，服务持续可用。
**上线前必须按第 8 节做一次实际恢复演练。**

## 6. 故障处理

| 现象 | 处理 |
|---|---|
| 401 未登录/会话过期 | 重新登录（会话 12 小时）；确认浏览器允许同源 Cookie |
| 403 权限不足 | 检查账号角色；写接口需 CSRF（页面自动携带，异常时重新登录刷新） |
| 导入被拒绝 | 按行级错误清单修正后重试；结构错误不静默丢行 |
| 计算超限 | 引擎返回贪心可行解并标注「未证实最优」+建议步长；可改用粗步长或后续引入优化器（见性能基准文档） |
| 恢复失败 | 确认备份文件名格式与来源合法性；用 CLI 恢复并查看报错 |

## 7. 容量 / 并发限制（如实声明）

- SQLite WAL：单写多读；写并发由 SQLite 串行化。适用单园区/企业小团队；
  高并发或跨机房需求超出本版本范围。
- **实测容量（2026-09-11 压测，docs/压力基准-v16.md）**：≤20 并发操作全链路
  零错误（引擎运行 P95 约 0.8–1.8s，WSL/Windows 实测）；30 并发仍零错误但
  引擎 P99 升至约 1.3–2.1s、响应明显变慢——适用边界维持 ≤20 并发。
- **大案例预期等待（2026-09-14 实测，docs/压力基准-v16.md 第五节）**：约 30 供给的
  大案例单发约 13–14 分钟、2–4 并发下单次约 18–20 分钟（全链路零错误）。大案例
  应作为单发后台任务使用，避免多名用户同时提交；该容量口径（≤20 并发）仍以
  小案例为准，不外推至大案例并发。
- **大案例预期等待（2026-09-15 并行化后复测，docs/压力基准-v16.md 第六节）**：
  30 供给单发引擎步实测 549s（**约 9–10 分钟**，全链路零错误），替代上一条
  串行口径的单发数字；2–4 并发未复测。大案例推荐走后台异步路径（≥16 供给
  自动启用）。
- **后台计算（v18 起）**：供给批次 ≥16 的任务点「运行计算」自动走后台异步路径
  （按钮实时显示已用时，大案例预计十几分钟），完成后自动加载结果；也可在 API 层
  用 `POST /api/tasks/{id}/runs?async=1` + `GET /api/runs/jobs/{job_id}` 集成。
  边界：同服务器同时只允许 1 个后台计算任务（第二个提交会收到明确提示）；
  作业为进程内存态，服务重启即丢失（需重新提交）；结果与同步路径逐位一致。
- 登录限流：同 IP 900 秒内最多 10 次登录尝试（防暴力破解，设计内行为）。经
  NAT/代理共用出口 IP 的现场 >10 并发同时登录会收到 429，错峰登录即可。
- 完整枚举上限：组合数 > 20,000 时返回可行解回退（详见 docs/性能基准-v10.md，
  100 批次引擎 3.4s 量级）。
- 导入体量：单次请求 ≤ 1 MB。

## 8. 客户验收清单（v11）

1. 新建任务 → 导入带错误 CSV → 行级错误定位 → 修正 → 幂等提交（失败整批回滚）。
2. 运行计算 → 勾选 2–3 方案对比 → 确认采购（服务端新鲜度校验+全局库存占用）。
3. 证据闭环：创建补证任务 → 提交结构化证据 → 审核通过/驳回 → 重算后门槛变化；
   历史证据版本可回放。
4. 记录结构化履约反馈（真实/模拟分开）→ KPI 面板（无实证如实显示）。
5. 备份 → 制造变更 → 恢复 → 任务/供给/选定方案/预留一致。
6. 跨任务库存：两任务争同一批次只允许总有效占用 ≤ 可供量。
7. 三角色账号验证（viewer 写接口 403）。
8. 指标口径核对（docs/试点交付模板-v10.md 第 2 节）。

## 10. 已知限制（v11）

- online 数据模式未实现（明确拒绝，不伪装）；多需求任务须逐条建任务。
- 切换时间/切换费用未知时 N-1 按产能上限口径标注，不冒充交付保证。
- 只测单家供应商失效（未启用共同失效模型，如实说明）。
- 证据任务列表前端分页 10/页；压力基准为小案例口径（2 供给穷举路径，
  docs/压力基准-v16.md）；大案例（30 供给）单发/低中并发已于 2026-09-14 实测
  （同文档第五节：单发约 13–14 分钟、2–4 并发约 18–20 分钟、零错误），更多并发
  未测、不外推（SQLite 万行内无风险）。
- Firefox/WebKit 未做浏览器级验收（本机仅 Chromium 内核验证）。
