# 数据源启用步骤：企业批次供需数据的合法获取与导入

- 编写日期：2026-09-03（按再生材料主线修订）
- 口径：供需数据由**企业自行发布**、园区运营方组织收集，本机处理不出网；系统不做爬取、不登录外部平台、不接入外部 API。

## 0. 当前状态（代码事实）

- 演示模式：`run.py --industry 再生PP --data-mode demo` 使用内置虚构供需数据（1 条需求 + 4 条供给），全程标注演示；
- 真实数据通道：本地 CSV 导入（`--data-mode local`），模板为 `templates/material_supply.csv`（供给批次）与 `templates/material_demand.csv`（替代需求）；
- 因子配置：`config/material_emission_factors.yaml`，因子缺失时输出待补证据，禁止用 0 代替。

## 1. 供给批次数据（material_supply.csv）

### 1.1 操作步骤

1. 供料企业（或受其委托的园区运营方）按模板填写批次信息：物料类别、聚合物类型、形态、颜色、牌号、熔指、水分、灰分、再生含量、可用质量(t)、可用时窗、产地、单价(CNY/t)、预处理方式、运输方式；
2. 为关键数值附上证据：熔指/水分/灰分等性能值以**检测报告**为准（注明报告编号、检测机构与日期）；质量以**过磅单**为准；无法提供证据的字段留空并注明「自发布声明」，系统按低可信等级处理并提示待核验；
3. 保存到 `data/input/material_supply.csv`（表头与模板一致；缺失必填列直接报错）。

### 1.2 字段证据等级（与系统可信等级对应）

| 证据类型 | 可信等级 | 说明 |
|---|---|---|
| 第三方检测报告 | 较高 | 注明报告编号、机构、日期，可追溯 |
| 过磅单/发货单 | 较高（质量字段） | 重量证据，注明单据编号 |
| 企业自发布声明 | 较低 | 仅作线索，涉及硬门槛的字段缺证据时进入待核验 |
| 无证据 | 缺失 | 因子/字段缺失输出待补证据，不默认通过 |

## 2. 替代需求数据（material_demand.csv）

1. 用料企业按模板填写：目标物料代码、用途、需求量(t)、最低再生含量、熔指区间、水分/灰分上限、可接受形态与颜色、需求时窗、目的地、原生基准价(CNY/t)、最大运距(km)；
2. 原生基准价用于计算绿色溢价（成本差 ÷ 净减排），需注明价格来源（合同价/询价记录）与日期；
3. 保存到 `data/input/material_demand.csv`。

## 3. 运行

```powershell
# 任意 Python 3.12+ 解释器（标准库 + PyYAML，见 README「快速开始」）
python run.py --industry 再生PP --data-mode local
```

验证行为：供需 CSV 缺必填列直接报错；数值字段非数字/负数/非有限值按行剔除并报告；因子编号不在因子表中 → 该方案输出待补证据。

## 4. 隐私与合规边界（答辩口径）

1. **数据由谁给**：企业/园区运营方自行发布，系统不爬取、不登录、不调用外部 API；
2. **数据不出本机**：所有数据保存在 `data/input/` 与 `output/`，系统不发送邮件、不上传、不发布，分析全程离线；
3. **字段最小化**：只采集匹配与核算必需字段（规格、数量、时窗、位置、价格、证据），不采集配方等工艺秘密；价格可用编号替代展示；
4. **书面授权**：试点前由园区运营方与参与企业书面确认数据授权与脱敏方式（模板见《试点验证方案.md》§7）；
5. **演示与真实分离**：演示模式与本地模式严格分离，演示数据不会静默混入真实数据。
