## 二、与现有因子结构的对接设计（不改引擎，只规范「条目录入」）

现有结构（`config/material_emission_factors.yaml`）：`factor_id / role / stage / material_code / value / unit / boundary / region / year / source_name / source_url / version / grade（演示假设|权威）/ applies_to / transport_included_in_factor`，外层 `accounting_convention`（边界兼容判定）与 `sensitivity` 注册表。引擎按 role 显式解析（`src/ledger.py resolve_factor`），**不硬编码因子 ID**——这决定了接入是「往表里加条目」，不是「改代码」。

1. **factor_id 命名规范**：`{来源}-{口径}-{物料}-{年份}`，与现行 `DEFRA-ARTIC-HGV-DIESEL-2024` 一致。示例：
   - `MEE-GRID-CF-CHINA-2024`（电力，如有需要）
   - `OPENLCA-RPP-PELLET-G2G-2025`（再生 PP 颗粒，gate-to-gate）
   - `CPCD-VIRGIN-PP-CTG-2022`（原生 PP，cradle-to-gate，如选用 CPCD 条目）
2. **条目准入门槛（每条真实因子必须齐全才允许 grade=权威）**：source_url 可访问、访问日期、许可类型与商用结论、单位换算式、边界声明原文摘录、区域代表性结论。建议（仅方案，不实现）在因子条目增加可选字段 `license_type / access_date / verification_note`；老配置缺省该字段时按现状兼容，不改校验语义。
3. **边界对齐映射**（接入时逐条执行）：
   - 基准材料：必须 cradle-to-gate（与 `virgin_boundary_keywords` 匹配）；
   - 项目材料：必须 gate-to-gate（与 `recycled_boundary_keywords` 匹配）。openLCA 再生塑料数据集自带 cradle-to-gate 与 gate-to-gate 两套，**选 gate-to-gate 套件**；
   - `transport_included_in_factor`：逐条核对数据集是否内含出厂运输/厂内物流，声明不匹配时先做显式拆分转换并记录，再入库；
   - 不满足约定 → 引擎现有「边界不兼容」阻断逻辑自动拦截，**不需要（也不允许）放宽校验**。
4. **单位换算**：材料统一 `kgCO2e/t`、运输统一 `kgCO2e/(t·km)`；CPCD 等来源如为其他单位（如 kgCO2e/kg），换算式写入 `source_name`/备注并保留两位以上有效精度，避免换算链引入静默误差。
5. **区域代表性分级**（写入每条 verification_note）：中国官方（MEE/CPCD）＞ 商业中国库（CLCD/ecoinvent 中国数据集）＞ 欧洲公开集（openLCA rPP，需声明「欧洲均值，中国试点仅作量级参考」）。演示期内 grade 体系不变：非权威一律「演示假设」。
6. **版本升级规则**：同一年度内修订 → `version+1`（旧值可在 git 历史追溯）；年度新版 → 新 factor_id（year 后缀），旧条目保留但不再被解析选中（role+material+transport_mode 匹配规则按「权威优先→年份降序→版本降序」自动选择，`resolve_factor` 已实现，无需改动）。
7. **护照兼容**：因子哈希取自运行输入快照（不回读当前配置），因子替换后历史护照可复算、新运行自动携带新哈希——接入动作对护照层零改动。

## 三、功能单位与系统边界对齐说明（口径不变）

- **功能单位冻结**：交付 1 t 满足需方规格的合格颗粒（`accounting_convention.basis` 不改）。
- **基准侧**：原生 PP 生产（cradle-to-gate）+ 基准运输（100 km 公路，演示假设，独立于候选做敏感性）。
- **项目侧**：再生 PP 生产（gate-to-gate：收集、分选、清洗、造粒）+ 候选运输（按批次距离与方式）。
- **废料起点**：cut-off——不向前追溯废物负担、不叠加处置信用；接入数据集若内含处置信用（如 0/100 分配法），必须转换或弃用，并在 verification_note 记录。
- **收率**：现行约定「收率损失已含在再生生产因子内」；所选再生颗粒数据集必须与该口径一致（openLCA 再生颗粒条目为成品颗粒出口，口径一致；若改用「片料」条目则含后续造粒差值，需显式转换）。

## 四、试点替换流程与回退方案

**替换五步（每次替换都出留痕 diff，经用户确认后合入——红线 5）**：

1. **锁基线**：复制当前 `material_emission_factors.yaml` 为 `material_emission_factors_v1_demo.yaml`（只读存档）；跑固定演示案例留存「替换前」四方数值（页面/API/DB/护照）。
2. **逐条替换（顺序固定）**：① 运输因子 2024→最新 DESNZ 年版（同方法学，风险最低）；② 项目材料因子（openLCA rPP 颗粒 gate-to-gate 或 CPCD 条目）；③ 基准材料因子（CPCD/ecoinvent 原生 PP cradle-to-gate）。每换一条跑一次 `validate_material_factors` 与演示案例重算。
3. **一致性校验**：全量测试 + 1 个演示案例 + 6 组随机独立穷举核验（因子数值变化不影响结构一致性，应全过）；核对 `resolve_factor` 选择日志（权威优先→年份降序）命中预期条目。
4. **口径发布**：此时演示案例数值**不再是冻结口径**，成为「演示口径 v2（真实因子重校准）」——必须单独出《重校准报告》（旧值→新值对照 + 差异归因）。已提交赛事材料（1000 字介绍、PPT、视频、报名 zip）**永不回改**（红线 6）；对内材料（README、演示网站、试点手册）统一更新并注明口径版本与日期。
5. **留痕**：每条因子生成 `旧 value → 新 value + source_url + 访问日期 + 许可` 的 diff 记录，归档 `docs/`。

**回退方案**：因子文件按版本存档（第 1 步副本 + git/备份快照）；任何口径争议 → 还原存档文件 → 重跑校验与演示案例核对（数值应与替换前逐位一致，因为引擎确定性）。回退演练纳入替换流程（替换后首次发布前做一次还原→再替换的演练）。

**试点检查点**：真实客户数据接入前，因子表必须达成「运输=权威、项目材料=权威、基准材料=权威或注明商业库采购中」三条；达不到则试点报告如实标注「演示因子」。
