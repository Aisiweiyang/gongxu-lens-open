# 试点最小闭环（2–4 周真实验证设计）

- 编写日期：2026-09-03
- 状态：**设计模板，全部事项待启动**。本文档不含任何已发生的访谈、合作、数据或成果；未发生事项一律标「待启动」，指标只给可测定义，不填成果值。

## 1. 闭环设计（一园区一起步）

首个试点限定：**一个园区、一个具体用途（非食品接触类工业包装/周转制品）、一个用料企业、3–10 个候选供给批次**。园区运营方（或循环化改造服务商）负责组织数据与验证动作，系统负责减少筛选与复核成本。

验证闭环（每步均待启动）：

```text
收集一个真实替代需求（用途、规格、数量、时窗、预算）
→ 收集 3–10 个真实供给批次（规格、产能、价格、证据）
→ 跑通「召回 → 硬门槛 → 证据价值排序 → 组合 → 决策护照」
→ 按系统建议执行送样/询价/补证（人工环节，系统只列任务）
→ 记录送样结论、成交/否决与真实履约数据
→ 对比情景测算与实际履约的成本、碳与韧性偏差
```

## 2. 两周/四周计划（全部待启动）

| 周 | 步骤 | 产出 |
|---|---|---|
| 第 1 周 | 园区确认试点范围；访谈用料/供料企业（三问：耗时卡点/预算归属/付费意愿）；收集供需数据并脱敏整理 | 访谈记录、数据清单、供需 CSV |
| 第 1–2 周 | 配置因子与业务约束；跑通匹配与方案生成；与企业核对门槛与因子口径 | 第一版决策护照、口径确认记录 |
| 第 2–3 周 | 执行证据任务（送样/询价/补证）；记录每项任务的关闭情况与结论 | 证据任务台账、送样结论 |
| 第 3–4 周 | 复盘：对比系统方案集与实际决策；统计八项指标；形成试点小结 | 试点小结、指标统计、改进清单 |

## 3. 核心指标（只给可测定义，成果值不填写）

| 指标 | 可测定义 |
|---|---|
| 首轮决策耗时 | 从供需数据就绪到拿到第一版决策护照的时间（小时/天），与人工比选耗时对比 |
| 候选召回率 | 系统召回且人工认为相关的批次数 / 人工筛出的全部相关批次数 |
| 硬门槛误放行 | 通过门槛但送样/人工复核后被否决的批次数 |
| 证据关闭率 | 已关闭（通过/否决/取得）的证据任务数 / 系统生成的证据任务总数 |
| 送样有效率 | 送样后进入成交或试用环节的批次数 / 总送样批次数 |
| 可行组合数 | 单次任务输出的非支配组合方案数 |
| 断供服务率 | N-1 模拟中，任一供方失效后仍能满足的需求质量比例 |
| 情景与履约偏差 | 成交方案的实际履约成本、运输排放与系统情景测算值的相对偏差（%） |

## 4. 数据与合规边界

- 数据由企业/园区运营方自行发布，只存本机，系统不上传、不发邮件、不出网；
- 展示使用代号与脱敏样例；价格可用编号替代；
- 数据授权：试点前由园区运营方与参与企业书面确认（模板见《试点验证方案.md》§7）；
- 演示数据与真实数据严格分开，指标只统计真实试点数据。

## 5. 绿色口径边界

- 试点只记录「情景测算值与实际履约的差异」；没有真实成交时只写情景测算，不写成已实现减排；
- 净减排按同一功能单位（交付 1 t 合格颗粒）与同一系统边界核算；演示因子须替换为经核实的因子后才能进入真实对比；
- 绿色溢价只称「当前系统边界下的情景边际减排成本」。

## 6. 停止条件

以下情况停止并如实说明：无法取得书面数据授权、无真实供需数据可收集、因子无法核实、试点单位要求接入公网或托管数据。
