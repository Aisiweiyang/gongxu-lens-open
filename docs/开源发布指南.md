## 可复现的本地验收

使用 Python 3.12+ 的全新虚拟环境：

```bash
python -m pip install -r requirements-test.txt
python scripts/check_project.py
python run.py --industry 再生PP --data-mode demo
python scripts/build_release.py
python scripts/prepare_public_release.py
```

`check_project.py` 要求完整运行依赖、所有测试通过且零跳过，再运行独立穷举核验。
独立脚本覆盖 1 个演示案例 + 6 组固定种子的随机案例；旧文档“47/47”不作为当前覆盖证明。
浏览器验证另需 requirements-dev.txt 与本机 Chrome/Edge，按 CONTRIBUTING.md 运行四套 E2E。

## 公开范围

`scripts/prepare_public_release.py` 从当前文件导出 `dist/public-source/` 与
`dist/gongxu-lens-public-source.zip`，并生成逐文件 SHA-256 清单。
它不切换分支、不改写历史、不上传、不删除本地原资料。

公开包保留源代码、测试、模板、配置、CI、Markdown 文档与演示截图；排除：

- 内部参赛目录、AI 协作过程档案与所有者本机操作文档；
- 运行数据库、业务输入与备份、缓存、虚拟环境、构建目录；
- 历史生成报告、E2E 输出文本与配置备份文件；
- 第三方 PDF 原件及本地生成的 Word/PDF 手册。来源链接与自有影子分析仍保留。

公开包与本地完整开发仓库的文档范围不同：CHANGELOG 的旧轮记录和文档中的本地
档案引用作为历史保留，不代表相应附件也已公开。

## GitHub 发布

正式公开仓库：[Aisiweiyang/gongxu-lens-open](https://github.com/Aisiweiyang/gongxu-lens-open)。
原 `Aisiweiyang/gongxu-lens` 保持私有，作为完整开发档案。

公开仓库从逐文件哈希校验通过的源码包建立，使用无父提交的初始提交；不导入旧仓库
历史、旧标签、旧 Release 或内部附件。当前文件的排除规则不会自动清理既有历史 blob，
所以后续同步仍使用明确的公开范围，并审查新增文件。

发布验收：

1. 核对公开文件清单和源码包 SHA-256；只提交清单中的源码文件。
2. 确认初始提交无父提交、默认分支为 `main`、许可证被 GitHub 识别为 MIT。
3. 启用并核验 Private vulnerability reporting，供 SECURITY.md 的私密报告入口使用。
4. 检查公开仓库 GitHub Actions：Linux Python 3.12/3.14，所有测试与独立核验通过。
5. 核对原仓库仍为私有；后续正式 Release 仅使用独立验证过的发行包。

源码包中的 `PUBLIC-MANIFEST.json` 用于校验导出时的文件字节；它不作为公开仓库的
跟踪文件，以免 Git 换行标准化后使清单过时。构建产物、业务数据库和虚拟环境继续忽略。
