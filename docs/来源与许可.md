## 0. 与旧清单的口径差异

桌面《清华绿创赛-GitHub先进经验清单.md》（2026-09-01，第二轮搜索）是本文件之前的预研口径。**以本文件为准**，差异如下：

1. 旧清单建议借鉴的 OpenSupplyChains、hock/Manifest（供应链可视化）、BinFuPKU/DPJF-MBS（双边匹配算法库）、neowalter/NEOXLINK-SDK（UNSPSC 分类）、greenroute-ai、TinHau-forecasting、Multi-task-building、samirsaci/supply-chain-optimization 等仓库**不在本项目参考清单内，不参考、不记录借鉴**。原因：仪表盘采用原生自包含 HTML（无外部依赖，不需要参考外部前端工程）；「分析→撮合→平台」的双边匹配属终局设想，不在本项目范围；greenroute-ai 等未列入方法来源优先级。
2. 旧清单将 LEONcaesar/Intelligent-Dual-Carbon-Management-System 列为「减碳模块参考」：**现改为不采用**（原因见 2.2）。
3. 旧清单将 nosgestesclimat 列为「权威性最高」的碳因子数据源：**现仅参考其因子数据结构，不采用其因子数值**（原因见 2.3）。
4. 旧清单建议答辩引用「IBM 官方采购优化方法」背书：本项目原则是「不得以 GitHub 星数、宣传文案或厂商背书代替方法验证」，**删除背书话术**，只保留方法流程层面的借鉴记录（见 1.3）。
5. 相对旧清单**新增**一个允许仓库：opensupplyhub/supplychaindata.exchange（企业、地点和关系数据结构）；旧清单曾列入的 openboxes/openboxes 已移出参考清单（其业务语义不再与主线相关）。

## 1. 允许阅读的仓库（记录产品结构或方法论启示）

### 1.1 Leoi-JR/industry-chain-matcher

- 地址：https://github.com/Leoi-JR/industry-chain-matcher
- 许可证：**无许可证文件**（API /license 返回 404）。仓库声明为 Python 项目，4 星，最近更新 2026-05-13。
- 核对内容：README（英文）+ 公开算法说明页。
- 产品结构：企业文档（经营范围、专利等）嵌入向量 → 与预设产业链图节点批量矩阵相似度 → 阈值门控匹配（特定链需要 L0 根节点相似度门控）→ catch-all 节点排除逻辑 → LLM 辅助阈值校准管线；自带 13 节点示例链 + 200 条 mock 文档。
- 本项目可借鉴的方法论启示（非代码）：
  1. **阈值门控 + 可解释淘汰**思路：本项目匹配流程采用「硬门槛 + 可配置评分 + 淘汰原因」，与其「门控 + 排除逻辑」同构，但实现完全独立（规则评分，不用嵌入向量）；
  2. **LLM 只做辅助校准、不做主流程**的定位：与本项目「语义分类仅作为可选增强接口、默认关闭」口径一致；
  3. 用 mock 数据离线跑通全流程的做法：与本项目演示数据包思路一致。
- 借鉴边界：仓库无许可证，**只参考其 README 描述的方法思路，不采用其任何代码、函数结构、提示词模板或示例数据**；本项目比其多两个维度：真实招投标买卖关系（它只做企业挂链）与绿色情景测算。

### 1.2 Eren-Jaeger-DEV/India-Procurement-Watch

- 地址：https://github.com/Eren-Jaeger-DEV/India-Procurement-Watch
- 许可证：**MIT**。12 星，最近更新 2026-07-12。
- 核对内容：README + 仓库 docs/ 目录说明。
- 产品结构：处理政府采购门户数据库导出 → 本地轻量仪表盘（React 前端 + Flask 后端）；板块包括风险引擎（异常中标方）、图算法社团检测、OpenSanctions 外部名单交叉核对、调查台（单标合同、重复中标、整数金额等红旗）、自然语言转 SQL 的 AI 查询台。
- 本项目可借鉴的方法论启示（非代码）：
  1. **证据链与免责声明**的写法：其 README 明确「异常不等于有罪」「名称匹配会产生误报，必须经官方注册系统核实身份」。本项目报告中的「口径边界」与数据可信等级说明按同等严格程度编写；
  2. 采购数据仪表盘围绕「谁在买、谁在卖、金额分布」组织板块，与本项目仪表盘板块 1/2 一致。
- 借鉴边界：MIT 许可允许复用，但本项目**不复制其代码**；只采用「仪表盘板块划分 + 免责声明写法」两个设计思路。本项目不做异常/腐败标记功能（红旗标记超出采购样本分析口径，且涉法风险高，不在本项目范围内）。

### 1.3 IBM/optimize-procurement-and-inventory-with-ai

- 地址：https://github.com/IBM/optimize-procurement-and-inventory-with-ai
- 许可证：**无许可证文件**（API /license 返回 404）。IBM 官方教程式仓库，38 星，最近更新 2025-09-17。
- 核对内容：README。
- 产品结构：案例教学流程——历史需求数据训练预测模型（SPSS Modeler）→ 预测需求输入决策优化（Decision Optimization）→ 在产能与成本约束下选择供货工厂与下单量 → 采购经理 Web 应用。
- 本项目可借鉴的方法论启示（非代码）：
  1. 「需求预测 → 需求-产能-成本约束优化 → 决策界面」的问题分解顺序，与本项目「硬门槛（资质、可供数量）+ 可评分项（成本、交期、距离、集中风险、碳排）」的分解同构；
  2. 优化结果必须落到「选哪个供应商、订多少」的决策语言，本项目的情景比较输出同样落到候选供应商对比。
- 借鉴边界：仓库无许可证且为 IBM 商业平台（Cloud Pak for Data）教程，**不采用其任何代码与教程文本**；答辩不使用「IBM 背书」话术（本项目不以厂商背书代替方法验证）。

### 1.5 opensupplyhub/supplychaindata.exchange

- 地址：https://github.com/opensupplyhub/supplychaindata.exchange
- 许可证：**CC0-1.0**（公有领域贡献）。7 星，最近更新 2025-06-25。
- 核对内容：README + wiki 中的核心 Schema 说明。
- 产品结构：供应链数据交换标准（SC-DEX）——JSON 结构的核心 schema 只含最小必要标识（位置 ID、组织 ID、关系类型），扩展 schema 由各行业/场景自行构建并与核心 ID 桥接；由多方治理委员会维护。
- 本项目可借鉴的方法论启示（非代码）：
  1. **核心最小化 + 扩展分离**的数据结构设计：本项目采购关系网络的节点/边契约保持最小字段集（企业 ID、名称、角色、产业链位置、来源），情景比较作为独立结构，与 SC-DEX 的设计原则一致；
  2. 企业与地点用稳定标识关联、关系显式成边——本项目买卖关系边（买方、卖方、交易次数、样本金额、项目列表、来源）同构。
- 借鉴边界：CC0 无任何限制，但本项目**不复制其 schema 文件**，只采用「最小核心 + 可扩展」的设计原则；本项目的关系数据来自采购样本，不对外发布数据集。

### 1.6 OCDS 与 WBCSD PACT 式数据质量分级（新增的方法参考）

- OCDS（Open Contracting Data Standard）：只借鉴其「公告/授标/合同/履约」分阶段的采购数据生命周期思想，为本项目本地采购 CSV 增加可选 `stage`、`currency`、`ids`、`items` 等字段，解决「公告、授标、合同、履约混在一起」的口径问题。本项目**不声称符合 OCDS**，也未运行其正式校验工具。
- WBCSD PACT 式数据质量分级：只借鉴「数据质量分级随因子/证据声明」的设计思路，本项目证据元数据采用实测/官方公开/供应商声明/估算/演示五级 + 核验状态，实现与 PACT 无关。
- 两者均为标准/方法文档层面的参考，未复制任何实现。

### 2.3 nosgestesclimat（incubateur-ademe/nosgestesclimat）

- 地址：https://github.com/incubateur-ademe/nosgestesclimat
- 许可证：**MIT**。法国 ADEME 官方孵化项目，167 星，最近更新 2026-09-01（活跃）。
- 仅可参考部分：**因子/规则的数据结构**——每条计算规则用 publicodes 语言写成「公式 + 数值 + 单位 + 来源 + 边界说明」，其中来源与边界说明随规则内嵌的做法，与本项目排放因子元数据字段（来源链接、系统边界、地区、年份、可信等级）的设计一致。
- 不采用原因：
  1. 它是**法国个人碳足迹**计算模型（消费、交通、饮食等），因子口径（法国个人消费）与工业物料货运不匹配，直接采用会造成口径错误；
  2. README 明示其部分数据（ecoinvent 来源）**受使用条件限制，不能自由复用**——不能因为仓库是 MIT 就假定其全部数据可复用。
- 本项目自己的因子数值须从适合中国货运口径的公开来源核实后写入，与 nosgestesclimat 无关。

1. 上述「方法论启示」只影响本项目的设计说明与文档，**不保留任何第三方的函数结构、调用顺序、示例数据和文案**；
