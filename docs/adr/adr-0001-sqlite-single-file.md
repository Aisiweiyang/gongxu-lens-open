# ADR-0001：存储层采用 SQLite 单文件（WAL）

状态：已接受（v10 起运行；v16 任务 5 补记）。

## 背景

试点面向单组织/单园区局域网部署（<20 并发，v16 压测后为实测口径），无专职运维；
数据需要事务一致性（确认采购、全局批次库存、审计），又要能「拷一个文件即备份/交付」。

## 决策

- 存储用 SQLite 单文件 + WAL 模式；每请求独立连接 + BEGIN IMMEDIATE 事务；
  SCHEMA_VERSION 幂等迁移；备份=文件级（恢复前 wal_checkpoint(TRUNCATE)）。
- 不引入数据库服务器（PostgreSQL/MySQL），不上云。

## 后果

- 正面：零运维、零依赖（stdlib sqlite3）、备份/恢复/交付极简（一个文件）、
  事务与审计完整；与「单组织独立部署、数据不出本机」的隐私口径一致。
- 负面：写并发由 SQLite 串行化——v16 压测（docs/压力基准-v16.md）证实 ≤20 并发
  无写锁瓶颈；若未来多组织/跨机房共用，需换服务端数据库（本版本范围外，如实声明）。
- 惰性过期预留、全局批次库存等逻辑依赖单写者语义，迁移到 C/S 数据库时需重审。
