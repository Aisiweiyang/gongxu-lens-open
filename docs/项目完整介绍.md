## 一、项目是什么

**供需透镜（SupplyLens）**：面向工业园区与制造企业的再生材料供需匹配和净减排
决策系统。它把园区内外分散的可利用余料、再生材料供给与企业替代需求连接起来，
在规格、数量、时窗、价格和运输约束下给出可落地的匹配与组合方案，并计算资源
循环量、净减排量与绿色成本——每个数字都能逐项展开手算。

回答的核心业务问题：**原本会被闲置、低值处置或外运的物料，能否在满足使用要求
的前提下就地替代原生材料，并证明净环境收益和经济可行性。** 首个场景为再生 PP
颗粒替代原生 PP（非食品接触工业包装/周转制品）。

**定位边界**：只描述本次需求与导入供给的匹配结果与情景核算，不构成全市场供需、
交易或合规结论；不适用于审计清单、监管报送、碳信用签发。净减排是情景核算，
不是实测或认证减排。

## 二、功能全景（三层应用）

### 1. 静态演示层（`run.py` → `output/` + `site/`）

一条命令生成四类互不覆盖的产物：Markdown 报告、HTML 报告、**离线单文件仪表盘**、
**评委网站**（单页叙事，含演示模式：←/→ 翻页、空格自动播放、F 全屏）。

- 替代性三态筛选（可比较/待核验/不符合）
- 证据价值排序（保守/乐观双情景反事实：先补哪个检测最可能改变结论）
- 组合供料完整前沿（Pareto 散点，支持口径切换、悬停联动）
- N-1 断供压力测试（补证影响 vs 采购策略影响两张分离对照）
- 净减排核算（逐项可手算账本）与绿色成本（成本/碳四象分类）
- 结论稳定性核查（±20%/±10% 确定性扰动，如实报告翻转）
- 决策护照（JSON Schema v2，绑定快照与口径）
- 企业检索与市场背景；站点支持深浅色跟随系统、打印样式

### 2. 试点工作台（`pilot/start_pilot.py`，SQLite 多用户）

浏览器操作台，覆盖业务闭环：新建替代任务 → 录入/导入供给批次 → 候选与证据
任务（补证闭环，版本化不可静默覆盖）→ 方案比较（Pareto + 成本/碳账本展开）→
确认采购（confirmed 预留，服务端新鲜度校验防超卖）→ 履约反馈（真实/模拟分开）→
决策护照下载。另有：

- **多需求撮合页**：跨任务稳定匹配建议（Gale-Shapley 容量变体），只读试算
  即算即返、不落库（ADR-0005），可导出打印友好的 HTML 建议单
- **三角色鉴权**：admin（用户/备份/审计）、editor（全业务）、viewer（只读，
  服务端强制 403）
- **工程能力**：pbkdf2 口令哈希、CSRF 双提交、登录限流（900s/10 次）、参数化
  SQL、入参限制、审计留痕、备份/恢复（SHA-256 清单）；大案例（供给 ≥16）自动
  转后台作业 + 进度轮询（ADR-0006，作业为进程内存态，重启即失如实告知）
- 界面跟随系统深浅色；断网/会话过期/防重复提交等容错行为

### 3. 引擎层（`src/`，被上两层调用，确定性算法）

| 模块 | 职责 |
|---|---|
| `material.py` | 三态硬门槛、组合供料（完整枚举 → 超限转 OR-Tools CP-SAT 精确完整三维前沿，ε-约束直接后继法，三锚点全局精确恒在，CAP 500 如实截断）、N-1 压测、敏感性核查、场景级并行化（输出与串行逐位一致，`SUPPLYLENS_PARALLEL_WORKERS` 可覆盖） |
| `ledger.py` | 净减排账本（功能单位：交付 1t 合格颗粒）、绿色成本与边际减排成本、因子极值区间确定性传播 |
| `material_match.py` | 名称标准化与召回（n-gram Dice + v13 阈值门控与兜底层） |
| `evidence_value.py` / `evidence_quality.py` | 证据价值排序（单动作/动作包）、证据质量八维评分 |
| `matching.py` / `matching_sheet.py` | 双边撮合引擎 v0 与建议单渲染 |
| `passport.py` | 决策护照（Schema v2：身份/哈希/账本 trace/未知项） |
| `visuals.py` | 零依赖内联 SVG（Pareto 散点/N-1 条形/区间图/双边关系图，长标签槽自适应） |
| `report.py` / `dashboard.py` / `site_builder.py` | 报告、仪表盘、评委网站渲染（单文件离线，深浅色） |
| `imports.py` / `validation.py` | CSV 导入行级体检、唯一领域校验层（表单/API/CSV 共用） |
| `greedy_baseline.py` / `scenarios.py` / `feedback.py` | 贪心基准、双情景、结构化反馈 |

**确定性文化**：相同输入 → 逐字节一致输出（测试锁定）；缺失因子/距离/价格
标记待补证，禁止用 0 代替；算法版本 material-v8，护照 schema v2.0.0。

## 三、代码结构与技术栈

```text
供需透镜-绿创赛/
├─ run.py / serve.py            # 演示层入口与本地服务（127.0.0.1，白名单静态服务）
├─ src/                         # 引擎层（见上表）
├─ pilot/                       # 试点工作台（db/auth/api/server/start_pilot/
│                               #   init_admin/import_sample/backup_restore + static/）
├─ config/                      # 行业配置、排放因子表（YAML）、证据动作
├─ templates/                   # 供给批次/替代需求/反馈 CSV 模板
├─ schemas/                     # 决策护照 JSON Schema（v1 保留迁移、v2 现行）
├─ tests/                       # 271 项自动化测试 + 四套真实 Chrome E2E
├─ benchmarks/                  # 求解基准/压测/耗时结构测量脚本与 raw 实测数据
├─ scripts/                     # 发行构建/验证、截图、自检、演示自检
├─ docs/                        # 全部文档（四区地图见 INDEX.md）
├─ dist/                        # 发行双包（仅由 scripts/build_release.py 白名单构建）
└─ site/ / output/              # 生成产物（网站、报告、仪表盘）
```

**技术栈**：Python 3.12+ 标准库 + PyYAML（`requirements.txt` 仅此一项）；引擎
超限场景可选 OR-Tools CP-SAT（未安装自动回退贪心，行为差异如实标注）；试点端
SQLite 单文件；前端零框架（原生 HTML/CSS/JS，内联 SVG 图表，无 CDN 无外部资源）。
**数据模型 v5**：`supplies` / `batches`（含可选 `external_id`）+ `relations`
三元组表，老库自动迁移。设计决策记录见 `docs/adr/`（六篇 ADR：SQLite 单文件、
求解器双路径互验、区间不进护照、不引入 ruff、撮合不落库、异步内存态）。

## 四、代码开发怎么做

### 两套环境（勿混用）

| 环境 | 干什么 |
|---|---|
| **Linux/WSL**（Python 3.14 实录，OR-Tools 9.15） | 全量单测、独立核验、引擎基准、压测 |
| **Windows `.e2e-venv`**（Playwright + 真实 Chrome） | 四套 E2E、截图、发行构建验证、试点启动；**无 ortools**，超限场景走贪心回退（已知差异） |

### 开发命令

```bash

python -m pytest tests -q                        # 全量 271 项（0 跳过，约 90–145s）
python docs/独立核验脚本-v10.py                   # 独立穷举核验 1 个演示案例 + 6 组随机案例（第三方法互验）
python -m pytest tests/test_docs_wording.py -q   # 用词门禁 4 项（改任何文档后必跑）
```
```bat
:: Windows（浏览器层改动后四套必跑，console 零错误）
.e2e-venv\Scripts\python tests\e2e_v12.py       && rem 冻结锚点四方核对 18 项
.e2e-venv\Scripts\python tests\e2e_round2.py    && rem 浏览器全流程 31 项
.e2e-venv\Scripts\python tests\e2e_v16.py       && rem 撮合页与建议单 17 项
.e2e-venv\Scripts\python tests\e2e_v18.py       && rem 容错与异步 UI 9 项
```

### 开发纪律（红线摘要，全 11 条见 SPEC-v17 第三节）

1. **引擎任何改动必须「优化前后数值逐位一致」或等价论证** + 穷举互验；冻结
   锚点 83,025 / 64,182 / 21,072.98 / 59,941.25 由 E2E 数值断言端到端把守。
2. 新增任何模块/页面/测试/文档**先登记发行白名单**（`scripts/build_release.py`
   顶部）再构建；README 相对路径引用的资源同样要随包。
3. 用户可见变更同步 `CHANGELOG.md`（Keep a Changelog 分类）；提交首行
   `vXX任务N：<做了什么>`，含关键验收数字；每任务一 commit、独立可回退。
4. 注释只写行为约束与不变式；移动/删除文件先 grep 全部引用。
5. 不降低业务规则让测试通过；不引入在线调用、随机性或新的运行时依赖。

## 五、怎么调试（按场景）

完整故障对照表与全部命令见《项目现状与使用调试指南.md》第五节，速查如下：

| 场景 | 路径 |
|---|---|
| 改了 Python 代码 | WSL 全量 + 独立核验；排查 500 用 `pytest -s 2>日志` 看服务器线程异常栈 |
| 改了文档/文案 | 用词门禁 4 项（历史陈旧词禁回流、答辩「100%」限定词窗口） |
| 改了浏览器层 | 四套 E2E 串行跑；偶发 RST/超时原样重跑一次，连续两次同点失败才按缺陷排查 |
| 性能问题 | `benchmarks/solver_benchmark_v14.py`（引擎曲线）、`load_benchmark.py --tag 新标签`（压测，勿覆盖既有 raw） |
| 发行重建 | `scripts/build_release.py`（WSL/任意）→ `scripts/verify_release.py`（Windows，14 项）→ `scripts/demo_selfcheck.py`（答辩前快查，9 项） |
| 登录 429 / 端口占用 / 临时目录锁 | 设计内限流等窗口；结束旧进程换端口；Windows 文件锁忽略自动回收 |
